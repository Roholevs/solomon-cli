# Solomon CLI

**Більші моделі ШІ на менших комп'ютерах. Один крихітний файл. Без встановлення. Ніщо не залишає ваш комп'ютер.**

- **Запускайте моделі, які не вміщуються:** `solomon optimize` робить велику модель меншою і швидшою на вашому комп'ютері. Модель 35B, яку llama.cpp не змогла запустити на Mac із 16 ГБ, відповідає зі швидкістю ~20 токенів/с.
- **Один крихітний файл:** одна програма менше 1 МБ (0,3–0,4 МБ для завантаження). Нічого не треба встановлювати: ні Python, ні залежностей.
- **Ніщо не залишає ваш комп'ютер:** у програмі немає жодного мережевого коду. Без облікового запису, хмари й телеметрії.
- **Швидко без налаштувань:** параметри швидкості підбираються автоматично для кожної моделі, а перед завантаженням моделі перевіряється пам'ять.
- **Mac, Linux і Windows:** GPU Apple на Mac, CPU на Linux і Windows.

*English: [README.md](README.md)*

> Solomon CLI **безкоштовний** і має **закритий код**. Тут лише документація, релізи та трекер задач. Умови описано в [LICENSE](LICENSE).

## Швидкість порівняно з llama.cpp

Наведено лише випадки, де Solomon швидший або де llama.cpp не може запустити модель. Медіана 3 запусків після прогрівального.

| Модель | Тест | llama.cpp | Solomon CLI 0.2.1 |
|---|---|---|---|
| Qwen3.6-35B-A3B UD-Q4_K_M (20,6 ГБ) | швидкість відповіді на Mac з 16 ГБ | **не працює** (зупиняється з «Insufficient Memory») | **20 токенів/с** з оптимізованою копією (11,7 ГБ), так само в розмові з першим повідомленням ~860 токенів |
| Qwen2.5-Coder-7B Instruct Q4_K_M | підсумок тексту ~340 токенів, 256 токенів | 21,8 токена/с | **27,5 токена/с** (той самий файл)|
| Qwen3.5-2B Q4_K_M | швидкість відповіді, 128 токенів | 63,8 токена/с | **65,8 токена/с** |

Виміряно 25 листопада 2026 року (рядок 35B: 26 листопада 2026 року, Solomon CLI 0.2.1) на MacBook Air з Apple M4 і 16 ГБ пам'яті, macOS 26.6, від мережі живлення, без інших важких застосунків, усі моделі на внутрішньому диску. llama.cpp збірка 12359 (Homebrew). *Оптимізована копія — менший файл, створений `solomon optimize`; її відповіді близькі до оригіналу, але формулювання можуть відрізнятися.

Як відтворити: команди наведено в англійському [README.md](README.md#speed-compared-with-llamacpp).

## Вимоги
- **macOS**: Mac з Apple Silicon (M1/M2/M3/M4 або новіший), macOS 14 Sonoma або новіша. Mac з Intel не підтримуються.
- **Linux**: x86_64 або arm64 (aarch64), glibc 2.39 або новіша (Ubuntu 24.04+, Debian 13+, Fedora 40+ тощо).
- **Windows**: Windows 10 або 11, x86_64.
- **Процесори x86_64** мають підтримувати **AVX2** і FMA (Intel Haswell 2013+ / AMD Zen 2017+).
- Щонайменше 8 ГБ пам'яті (для моделей середнього розміру бажано 16 ГБ+).

На Linux і Windows програма поки що працює на CPU, тож вона повільніша, ніж на Mac з тією самою моделлю; малі моделі (0,5B–4B) працюють добре. Прискорення на GPU для Linux і Windows заплановане. Команди, параметри й вивід однакові на всіх платформах.

## Встановлення
### macOS
1. Завантажте `solomon-cli-<версія>-macos-arm64.zip` зі сторінки [Releases](../../releases).
2. За бажанням перевірте контрольну суму: `shasum -a 256 -c SHA256SUMS --ignore-missing`
3. Розпакуйте архів і перемістіть файл у PATH:
   ```sh
   unzip solomon-cli-*-macos-arm64.zip
   sudo mkdir -p /usr/local/bin && sudo mv solomon /usr/local/bin/
   # або без sudo: mkdir -p ~/bin && mv solomon ~/bin/ && echo 'export PATH="$HOME/bin:$PATH"' >> ~/.zshrc
   ```
4. Перевірте: `solomon --version`

Якщо macOS пише, що «не вдається перевірити розробника», зніміть позначку карантину (лише для файлів, завантажених із цих Releases): `xattr -d com.apple.quarantine /usr/local/bin/solomon`

Встановлення через Homebrew з'явиться згодом.

### Linux
1. Завантажте `solomon-cli-<версія>-linux-x86_64.tar.gz` (на ARM — `-linux-arm64.tar.gz`) і `SHA256SUMS` зі сторінки [Releases](../../releases).
2. За бажанням перевірте: `sha256sum -c SHA256SUMS --ignore-missing`
3. Розпакуйте й встановіть:
   ```sh
   tar -xzf solomon-cli-*-linux-*.tar.gz
   cd solomon-cli-*-linux-*/
   chmod +x solomon
   sudo install -m 755 solomon /usr/local/bin/solomon
   # або без sudo: mkdir -p ~/.local/bin && cp solomon ~/.local/bin/
   ```
4. Перевірте: `solomon --version`

Чи підтримує процесор x86_64 AVX2: `grep -o -m1 avx2 /proc/cpuinfo` (виведе `avx2`, якщо так).

### Windows
1. Завантажте `solomon-cli-<версія>-windows-x86_64.zip` зі сторінки [Releases](../../releases).
2. За бажанням перевірте суму в PowerShell і порівняйте з `SHA256SUMS`: `Get-FileHash .\solomon-cli-*-windows-x86_64.zip -Algorithm SHA256`
3. Правою кнопкою на архіві → **Видобути все…**, потім перемістіть `solomon.exe` у теку, наприклад `%LOCALAPPDATA%\Programs\Solomon`.
4. Додайте теку до PATH: Пуск → «Змінити змінні середовища для свого облікового запису» → **Path** → **Змінити** → **Створити** → вставте шлях → OK.
5. Відкрийте **новий** термінал (Windows Terminal, PowerShell або cmd) і виконайте `solomon --version`.

**SmartScreen («Windows захистила ваш ПК»)**: програма ще не підписана сертифікатом для Windows, тому під час першого запуску може з'явитися попередження. Натисніть **Докладніше** → **Усе одно запустити** або у властивостях `solomon.exe` позначте **Розблокувати**. Робіть це лише для файлів із цих Releases.

Кирилиця працює у Windows Terminal і PowerShell: програма сама перемикає консоль на UTF-8.

## Де взяти модель
Потрібен файл у форматі **GGUF**. Тисячі таких моделей є на [Hugging Face](https://huggingface.co/models?library=gguf). Підтримуються популярні відкриті чат-моделі, зокрема родини **Llama** і **Qwen** (Qwen2, Qwen3, текстові Qwen3.5). Якщо модель розбита на кілька файлів (`...-00001-of-00003.gguf`), вкажіть **перший** із них.

| Пам'ять комп'ютера | Розмір моделі |
|---|---|
| 8 ГБ | 0,5B–3B параметрів |
| 16 ГБ | до 8B |
| 32 ГБ+ | 14B і більше |

## Швидкий старт
```sh
solomon chat --file ~/Models/Qwen3-0.6B-Q8_0.gguf
```

## Команди
Загальна довідка: `solomon help`. Довідка до окремої команди: `solomon <команда> --help`. Кожен параметр має значення (`--назва значення`).

**`solomon chat`** — інтерактивний чат. Напишіть повідомлення й натисніть Enter. `/reset` очищає розмову, `/exit` або Ctrl-D завершує роботу.

| Параметр | Типово | Опис |
|---|---|---|
| `--file` | обов'язковий | шлях до `.gguf` |
| `--context` | 8192 | скільки токенів розмови бачить модель |
| `--max-tokens` | 1024 | максимальна довжина відповіді (до 8192) |
| `--threads` | auto | кількість потоків CPU (1–32) або `auto` = кількість продуктивних ядер |
| `--memory-mib` | 512 | пам'ять під розмову, МіБ |
| `--temperature` | 0.7 | креативність, 0–5. `0` — завжди найімовірніше слово (та сама відповідь щоразу) |
| `--top-p` | 0.9 | вибір лише серед найімовірніших слів, що разом дають цю частку |
| `--top-k` | 0 (вимк.) | вибір лише серед N найімовірніших слів |
| `--min-p` | 0 (вимк.) | пропускати слова, менш імовірні за цю частку від найкращого |
| `--repeat-penalty` | 1.1 | менше повторів слів з останніх 256 токенів (`1` — вимк.; `--repeat-window N` змінює 256) |
| `--seed` | випадковий | той самий seed і той самий запит — та сама відповідь |

Відповідь, що почала повторювати той самий фрагмент знову і знову, зупиняється автоматично. `solomon bench` приймає ті самі `--temperature`, `--top-p`, `--repeat-penalty` і `--seed`.

Моделі Qwen3 спершу «міркують» усередині `<think>…</think>`. Щоб це пропустити, додайте `/no_think` у кінці повідомлення.

**`solomon complete`** — продовжує текст. Параметри: `--prompt TEXT` (без нього текст читається зі stdin, до 4096 байт) і `--count N` (типово 16, максимум 128).
```sh
solomon complete --file model.gguf --prompt "Столиця Франції —" --count 12
```

**`solomon bench`** — вимірює швидкість моделі на вашому комп'ютері і виводить JSON (час завантаження, час до першого токена, токени/с). Параметри: `--prompt`, `--count` (типово 128, максимум 1024).

**`solomon optimize`** — робить модель меншою і швидшою на цьому комп'ютері; якість відповідей лишається близькою до оригіналу. Параметри: `--file` (модель, вона не змінюється) і `--out PATH` (типово поруч із моделлю, `НАЗВА.solomon`). Див. [Оптимізувати модель](#оптимізувати-модель).

**`solomon model-info`** — перевіряє GGUF-файл і виводить базові відомості.

**`solomon --version`** — показує версію. Код виходу: 0 при успіху, 1 при помилці.

## Оптимізувати модель

Великі моделі часто не вміщуються в пам'ять комп'ютера, і тоді працюють повільно або не працюють зовсім. `solomon optimize` створює меншу копію моделі, налаштовану для цього комп'ютера. Оригінальний файл не змінюється.

```sh
solomon optimize --file ~/Models/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf
solomon chat --file ~/Models/Qwen3.6-35B-A3B-UD-Q4_K_M.solomon
```

- **Найкраще для великих моделей** (від 3 ГБ), особливо тих, що великі порівняно з пам'яттю. Менші моделі й так працюють добре, тож їх не змінюємо.
- **Якість лишається близькою до оригіналу.** Формулювання відповідей можуть трохи відрізнятися.
- **Потребує мало пам'яті** під час роботи й показує прогрес і час, що лишився. Потрібне вільне місце на диску для нового файлу; Solomon перевіряє це заздалегідь.
- `solomon chat` з великою моделлю підкаже, якщо оптимізація допоможе, або якщо оптимізована копія вже лежить поруч.
- Поки що лише моделі з одного файлу.

| Модель | До | Після | Швидкість до | Швидкість після |
|---|---|---|---|---|
| Qwen3.6-35B-A3B UD-Q4_K_M | 20,6 ГБ | 11,7 ГБ | не вміщується в 16 ГБ* | 20 токенів/с |

Виміряно на MacBook Air з Apple M4 і 16 ГБ пам'яті, модель на внутрішньому диску. Якщо оптимізована модель вміщується в пам'ять, Solomon повністю зчитує її перед першою відповіддю («Loading model... 45%»), тож відповіді не чекають на диск. *llama.cpp зупинилася з «Insufficient Memory» на оригінальній моделі 35B.

## Поради щодо швидкості
- **Автоматична перевірка пам'яті.** Перед завантаженням Solomon порівнює, скільки пам'яті потрібно моделі, з вільною пам'яттю. Якщо вистачає, модель повністю завантажується в пам'ять для найкращої швидкості; якщо пам'яті мало, виводиться коротка порада закрити інші застосунки, а модель читається з диска за потреби.
- **Тримайте моделі на внутрішньому диску.** Зовнішні USB-диски читаються набагато повільніше; з власного диска комп'ютера модель завантажується й відповідає швидше.
- Обирайте модель, яка вміщується в пам'ять: файл не більше ~60% від обсягу RAM.
- Закрийте застосунки, що займають багато пам'яті.
- Менші варіанти файлу моделі працюють швидше.
- Перший запуск після завантаження повільніший.
- Порівнюйте моделі за допомогою `solomon bench`.
- На Linux і Windows (CPU) зазвичай найшвидше типове `--threads auto` (кількість продуктивних ядер); на CPU найшвидші формати Q8_0 і Q4_K.

## Типові проблеми
- `Model file not found`: перевірте шлях (шляхи з пробілами беріть у лапки).
- `Not a GGUF model file`: потрібен саме `.gguf` файл.
- `command not found`: файл не лежить у PATH.
- `bad CPU type`: у вас Mac з Intel, він не підтримується.
- `Illegal instruction` (Linux) / збій при запуску (Windows): процесор x86_64 без AVX2 не підтримується.
- `Exec format error` (Linux): не той архів — на ARM потрібен `linux-arm64`, на Intel/AMD — `linux-x86_64`.
- `GLIBC_2.xx not found` (Linux): надто старий дистрибутив, див. Вимоги.
- `'solomon' is not recognized...` (Windows): тека не в PATH або треба відкрити новий термінал.
- Повільна робота: модель завелика для вашої пам'яті.
